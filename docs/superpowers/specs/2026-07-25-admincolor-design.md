# Групповые цвета админов в OOC

## Цель

Добавить в существующую F7-панель отдельный модуль, доступный только админам с правом `Host`. Модуль позволяет выбирать цвет OOC для уже существующих групп админов (`AdminRank`). Все админы, относящиеся к группе, автоматически используют цвет группы в OOC-чате.

## Согласованное поведение

- В модуле отображаются только уже созданные группы админов.
- Для каждой группы Host может указать HEX-цвет, сохранить его или сбросить.
- Пустое значение означает, что цвет группы не задан.
- Цвет группы имеет приоритет над персональным `AdminOOCColor`.
- Если цвет группы не задан, сохраняется текущий fallback: персональный цвет применяется только при наличии `AdminFlags.NameColor`.
- Изменение цвета применяется к онлайн-админам этой группы без переподключения.
- Сервер повторно проверяет `AdminFlags.Host` при открытии и каждом изменении; клиентская кнопка скрывается обычной системой проверки команд.
- Настройка не создаёт и не редактирует группы и не меняет состав групп.

## Архитектура

1. В `AdminRank` добавляется nullable-поле `OOCColor`, сохраняемое в отдельной миграции.
2. `AdminManager` передаёт цвет текущей группы в `AdminData`, поэтому сервер чата может получить цвет без отдельного запроса к БД на каждое сообщение.
3. Общий resolver задаёт приоритет: цвет группы → персональный цвет при `NameColor` → отсутствие override. Его правила покрываются unit-тестами.
4. В F7 AdminTab добавляется Host-команда `adminooccolors`, открывающая новый EUI.
5. EUI получает список групп, валидирует HEX на сервере, сохраняет значение через существующий `UpdateAdminRankAsync` и вызывает `ReloadAdminsWithRank` для обновления онлайн-сессий.
6. Клиентское окно строится программно в стиле существующих `_AU14`-окон: строка группы, HEX-ввод, предпросмотр, сохранение и сброс.

## Границы изменения

Персональная команда `setadminooc` остаётся без изменений и продолжает работать как fallback для админов без цвета группы. Существующие группы и их права не мигрируются и не пересоздаются.
